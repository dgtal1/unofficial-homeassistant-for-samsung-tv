# Home – Home Assistant TV client for Samsung Tizen

A native Tizen web app (plain HTML/CSS/JS, no framework) with an Apple Home style
interface. It connects to Home Assistant over WebSocket and **mirrors a Home Assistant
dashboard**: views become tabs, sections/cards become groups of tiles.

## 1. Configure (one file)

Edit `src/js/config.js`:

- `url`: address of your Home Assistant, e.g. `http://192.168.0.14:8123`
- `token`: long-lived access token (HA profile -> Security -> Long-lived access tokens).
  Never share it; it is stored inside the app on your TV.
- `dashboard`: fallback dashboard url_path (`"samsung-tv"` by default; `null` = the default dashboard), used only
  when the HA profile of the token's user has no dashboard assigned. The app reads the dashboard assigned to the user
  in the HA profile (`frontend/get_user_data`, key `core`, field `default_panel`). On a real TV the picker is hidden and
  that profile dashboard is always used. In the emulator (detected from the product model / systeminfo) and in a desktop
  browser the picker is available (gear icon -> Dashboard) and a saved choice wins over the profile.
- `allowDashboardChange`: `false` by default; set `true` to show the dashboard picker on a real TV too.
- `columns`, `tapOpensDetails`, `longPressMs`: optional tuning.
- `notificationsIgnore`, `notificationSound`: notification options (see "Notifications" below).

Tip: create a dedicated HA user for the TV and generate the token for that user.

## 2. Build and install

Open the `src` folder in VS Code (trust the workspace), then with the Tizen TV extension:
Certificate Manager (Samsung certificate with the TV's DUID) -> Build Signed Package ->
Launch Application (TV in developer mode, IP set in the extension settings).

## 3. Remote control

| Key | Action |
|---|---|
| Arrows | move focus (tabs <-> tiles, sliders: left/right changes value) |
| OK | lights/switches/fans/covers: toggle; scenes/scripts/buttons: run; others: details |
| Hold OK (or Info) | details with sliders (brightness, color temperature, target temperature, position, volume) |
| Return | close details -> go to top -> exit app |
| Up (on the tab bar) | jump to the gear icon; Left returns to the tabs |

Locks, climate, media players, cameras and sensors always open details on OK
(no accidental unlocking).

## 4. What is mirrored from the dashboard

Views: `visible` is honoured like in the HA frontend (hidden for everyone, or only for the listed
users - the token's user is read with `auth/current_user`); subviews are hidden.
Card-level `visibility` conditions are not evaluated yet.

Supported: `tile`, `button`, `entity`, `sensor`, `light`, `thermostat`, `media-control`,
`weather-forecast`, `picture-entity`, `entities`, `glance`, `picture-glance` (entities),
`grid`, `horizontal-stack`, `vertical-stack`, `heading`, `conditional` (always shown),
sections views and masonry views.

Skipped: `custom:*` cards, markdown, graphs, maps, iframes, `area`, etc.
The list of skipped cards is shown in the diagnostics screen (gear icon, top right).
If the dashboard cannot be read, entities are grouped by type instead.
When you save the dashboard in the HA editor, the TV reloads it automatically.

## 5. Settings and dashboard picker

Gear icon (top right; from the tab bar press Up) -> **Settings**:

- **Dashboard**: lists the dashboards available to the token's user (same list as the HA sidebar),
  marks the current one. Picking one saves it in the app and reloads the view immediately.
- **Visual style**: Cupertino (default) or Simple Glass (a glassy, convex look; the same colours).
- **Language**: Automatic, Polski or English (see "Language" below).
- **Diagnostics**, **Reload dashboard**, **Close**.

The selection is stored in the app's web storage and survives restarts. Reinstalling the app
may clear it. Dashboards generated automatically by HA (strategy dashboards without views)
cannot be mirrored; the app tells you and shows entities grouped by type instead.

## 6. Diagnostics

The gear icon (top right; from the tab bar press Up) -> Diagnostics shows the web engine version (Chromium), Tizen version,
screen size, HA version, connection, skipped cards and a frame counter. Use it in the emulator and on the TV.
The list scrolls with Up / Down (the buttons below it always stay on screen).

## 7. Built-in dashboards (generated in the app)

The dashboard picker (gear -> Dashboard) offers, besides the dashboards from HA, two entries generated by the app
from the area, device and entity registries (`config/area_registry/list`, `config/device_registry/list`,
`config/entity_registry/list`, falling back to `list_for_display` if refused):

- **Home Assistant – Overview (generated)**: a recreation of the built-in HA Overview: summaries (Lights, Climate,
  Security, Media players, Maintenance, Weather) and Areas. Summary and area tiles open subviews (Back returns).
  HA builds its Overview dynamically in the frontend and it cannot be read through `lovelace/config`, so it is
  recreated here: it looks similar, but it is not identical.
- **Apple Home (rooms)**: a "Home" tab (summaries, scenes) plus one tab per room.

The fallback layout (used when the selected dashboard cannot be loaded or is empty) is the Apple Home layout by area;
if the registries are not available to the token's user, entities are grouped by type in a single "Home" view.

Not verified on a real HA: whether the registry commands are available to a non-admin user, and how exactly the
summaries match the HA Overview. The diagnostics field "Layout source" shows what actually worked.

## 8. Your own dashboard in the Overview style (`dashboard/`)

`dashboard/przeglad-apple.yaml` is a ready layout to paste into the raw configuration editor of an HA dashboard
(replace `/dashboard-dom/` with your own URL and the `zmien_…` entities with yours). The app supports tiles with
`tap_action: navigate` and `subview: true` views (a tile opens a subview, Back returns; holding OK on an entity
tile opens its details). `dashboard/pomocnicze-encje.yaml` contains example helper entities (a "Security" sensor,
an average temperature).

## 9. Visual style

Settings (gear icon) -> **Visual style** switches between **Cupertino** (default) and **Simple Glass** (a glassy,
convex effect, the same colours). The choice is remembered and works on the TV and in the emulator.

## 10. Language

Settings -> **Language** selects the app language: **Automatic** (default: Polish when the TV / browser language is
Polish, English otherwise), **Polski** or **English**. The change applies immediately and is remembered. The app's
own texts are translated (states, settings, diagnostics, notifications, generated dashboards); names that come from
Home Assistant (entities, areas, dashboards) are left as they are. All texts live in `src/js/i18n.js`; to add another
language, add a new dictionary next to `PL` and `EN`.

## 11. Notifications

The bell in the top bar (next to the settings gear) shows HA persistent notifications (`persistent_notification`),
read only: OK opens the list, OK on an item expands / collapses its text, Back closes it. A red dot with a counter
appears and disappears with an animation; a new notification rings the bell and plays a sound
(`src/sound/notify.wav`, can be turned off with `notificationSound: false` in `js/config.js`).

By default the list is read only. With `notificationsDismiss: true` in `js/config.js` every notification gets a × button
(RIGHT moves onto it, OK asks for confirmation) and the list ends with a **Dismiss all** button (also confirmed). The list
scrolls with the focus (UP / DOWN) and the buttons below it stay on screen. Dismissing removes the notification in Home
Assistant too, so it needs a token user that may call the `persistent_notification.dismiss` service; hidden notifications
(`notificationsIgnore`) are never dismissed.

Notifications are hidden with the `notificationsIgnore` list in `js/config.js`: `"id"`, `"prefix*"` or
`"title:part of the title"`. Diagnostics shows the state of the notification connection and the IDs of hidden ones.
If the subscription does not work for the token's user, the app reads the list every 30 s; if that fails too,
the bell is hidden.

## Tested on a real TV

Tested on a Samsung S95B (Tizen 6.5) with a real Home Assistant: loading and live reloading of the dashboard,
remote control keys (Return, Info / long OK), animations and page transitions, the Simple Glass style, the dashboard
picker (`allowDashboardChange`), notifications (list, sound) and dismissing them (`notificationsDismiss`), and the generated
dashboards for a non-admin token user.

Not verified yet:

- Light colours and effects on a real device with effects (e.g. Twinkly); tested only against a mock server.
